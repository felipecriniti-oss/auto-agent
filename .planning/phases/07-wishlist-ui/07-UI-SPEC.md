# Phase 7 — UI Design Contract — Wishlist UI

> Visual and interaction contract for Phase 7 (Wishlist UI). Generated by gsd-ui-researcher from PRD v3, Phase 5 design language, Phase 6 hook surface, and the existing `WishlistModule` Zustand scaffold. Verified by gsd-ui-checker.

**Product frame lock (from PIVOT-3 + PRD v3 NG4):** This UI is for the B2B lojista. PF is never addressed, never a user, never hinted at in copy. Phase 7 is pure "lojista describes car-target" — no live agent thread, no negotiation theater, no outreach status. That UX returns in deferred Phases 10/11/12. Any copy or chrome that suggests "o agente está negociando agora" is out of contract.

**Carryover lock (from Phase 5 `WishlistModule.tsx`):** The visual language is already established in code — slate surfaces, Fraunces for hero/editorial headings, Geist for body/UI, `#4C46DC` accent reserved to primary CTAs + selected chip state. Phase 7 **preserves** this treatment and swaps Zustand for the `useWishlists()` hook from Phase 6. This spec does not invent a new system; it codifies the existing one and extends it to cover gaps (form fields added, LocalidadePicker adopted, preview pane, onboarding wizard).

## Spacing Scale

8-point scale (multiples of 4). All gaps/padding in this phase resolve to these tokens via Tailwind defaults (`gap-1 → 4px`, `gap-2 → 8px`, `gap-4 → 16px`, `gap-6 → 24px`, `gap-8 → 32px`, `gap-12 → 48px`, `gap-16 → 64px`).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-label gap inside inline rows; chip vertical padding (py-0.5 = 2px allowed for tag micro-type only) |
| sm | 8px | Between form chips in a wrap group; stacked label→input gap (`space-y-1.5` = 6px allowed for tight label-to-input pairing) |
| md | 16px | Default field-to-field gap inside a section; card padding on mobile |
| lg | 24px | Section-to-section gap inside the form; header-to-grid gap on the module page; card padding on desktop (`p-5` = 20px is existing carryover — acceptable) |
| xl | 32px | Wizard step padding; top padding of module page on md+ |
| 2xl | 48px | Drawer content wide-margin breathing (not currently used; reserve for onboarding celebratory step) |
| 3xl | 64px | Not used in this phase |

Exceptions (preserved from Phase 5 carryover, do not refactor during Phase 7):
- `px-1.5 py-0.5` (6px/2px) for chip/badge text — tag micro-type standard
- `p-5` (20px) for wishlist card padding — existing carryover, do not change to 24 without a separate visual audit
- `h-11` (44px) for form controls — touch target for combobox/select triggers (LocalidadePicker standard)

## Typography

Three sans sizes + one display size. Two weights (400 regular, 600 semibold). One mono eyebrow style. Line-heights: 1.2 for headings/display, 1.5 for body.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Body | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 (`leading-6` via Tailwind default on sm) | Geist | Card body copy, form hint text, list items, chip labels, muted metadata |
| Label | 12px (`text-xs`) | 500 (`font-medium` allowed for labels; semibold reserved for emphasis) | 1.33 | Geist | Field labels, dd/dt rows, chip copy |
| Heading | 18px (`text-lg`) | 600 (`font-semibold`) | 1.2 | Geist | Card titles, drawer header, section subheaders |
| Display | 24–30px (`text-2xl md:text-3xl`) | 600 (`font-semibold`) | 1.1 (`tracking-tight`) | Geist (fallback) / Fraunces (editorial variant for empty-state hero + onboarding hero) | Module `h1` "Minhas Wishlists"; onboarding wizard hero |

Editorial/display Fraunces usage is reserved for:
- Onboarding wizard hero "Cadastre seu primeiro carro-alvo" (single instance per page)
- Empty-state h2 "Ainda sem wishlists" (single instance)

Mono eyebrow (JetBrains Mono, 10px, font-semibold, `uppercase tracking-[0.18em]`, `text-slate-500 dark:text-slate-400`) is reserved for LocalidadePicker field labels ("UF", "Cidade") to signal the adopted editorial treatment from Phase 6 onboarding. Do not introduce additional mono eyebrow labels elsewhere in the form — regular `Label` is the default for every other field.

**Weight rule:** only 400 and 600 allowed in-component. 500 appears exclusively inside chip/tag micro-type (`font-medium text-xs`) — preserved from Phase 5 carryover and treated as part of the chip primitive, not a third weight.

## Color

60/30/10 split applied to this phase. All colors resolve through CSS variables (`--background`, `--card`, etc.) or Tailwind slate-* utilities that pick up the dark-mode fallback layer already established in `globals.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` (oklch 1 0 0 light / oklch 0.145 0 0 dark ≈ slate-950) | Module page surface, drawer backdrop backdrop-blur bg |
| Secondary (30%) | `bg-white` (light) / `slate-900` via fallback layer (dark) | Wishlist cards, drawer sheet, form fieldset surfaces, empty-state box |
| Accent (10%) | `#4C46DC` brand indigo (exposed as `--color-brand`, `--color-brand-soft`, `--color-brand-dark`) | See reserved list below |
| Destructive | `--destructive` (oklch 0.577 0.245 27.325) + slate-compatible `text-red-600` / `hover:bg-red-50` | Delete wishlist action only |

**Accent (`#4C46DC`) reserved for — exact list, do not extend:**
1. Primary CTA background on "Nova Wishlist" button (module header)
2. Primary CTA background on "Criar primeira wishlist" button (empty state)
3. Primary CTA background on "Salvar wishlist" submit button (drawer footer)
4. Primary CTA background on "Ver X anúncios compatíveis" preview expand button
5. Selected state of `ChoiceChip` (fuel / transmission / armored / UF multi-select)
6. Empty-state icon container (`bg-[#4C46DC]/10` at 10% opacity + icon at solid `text-[#4C46DC]`)
7. Onboarding wizard hero icon treatment (single instance, mirrors empty state)

**Accent NOT allowed for:**
- Card borders (use slate-200 / slate-800)
- Card hover shadow (use default shadow-md)
- Status badges "Ativa" / "Pausada" (emerald / amber, preserved from Phase 5)
- Link text inside body copy (no such links in this phase; if added, default is slate-900)
- Section headers / form labels / hint text
- Focus rings (shadcn default `ring` token is slate-neutral; accent ring is out of contract)

**Semantic palette allowed (status colors) — carryover from Phase 5, no change:**
- Active state: emerald-50/700 (light), emerald-950/300 (dark)
- Paused state: amber-50/700 (light), amber-950/300 (dark)
- Blindado "Só blindado" warn chip: amber-50/700

**Dark mode:** all slate-* utilities in this phase flow through the `.dark` fallback layer in `globals.css` — no per-component `dark:bg-*` annotations are required for chrome (card bg, page bg, borders, body text). Explicit `dark:` variants are still required for component-specific color choices (emerald/amber badges, red destructive, indigo accent) and are already present in the Phase 5 carryover — Phase 7 preserves them.

## Interaction Contracts

### Entry point

- Wishlist is the primary module. Sidebar label: `Minhas Wishlists` (replaces the Phase 5 "Marketplace" label for this slot; old "Marketplace" → renamed to "Oportunidades" in Phase 12 when that module comes online).
- Module renders at route `/app` when `useWishlists()` returns `data.length > 0`, else renders empty state with hero CTA.

### Form invocation

- **Desktop (≥ md / 768px):** Right-side sheet, fixed, `w-[560px]`, z-50, with dimmed backdrop (`bg-slate-900/40 backdrop-blur-sm`). Carried over from Phase 5.
- **Mobile (< md):** Full-screen `dialog` (shadcn `Dialog` primitive), `w-full h-full`, no backdrop. Header has close button + title; footer sticks to bottom; content scrolls between.
- **Decision locked:** Sheet/dialog over dedicated page. Rationale: lojista edits fields iteratively while watching the preview pane count update live; full-page route would break the "preview as I type" loop. Onboarding uses a **full-page wizard** (different context — single-shot, celebratory) — that's the only full-page variant.

### Form submission flow

1. User types → `react-hook-form` updates state → `zod` validates → `matchingEngine` reruns on debounce (400ms) → preview count updates.
2. User clicks "Salvar wishlist" → `useCreateWishlist().mutateAsync(input)` fires → optimistic UI (card appears in grid immediately, status "Ativa") → `sonner` toast on success → sheet closes.
3. On mutation error → sheet stays open, `sonner` error toast fires, optimistic card reverts. Submit button re-enables.
4. Submit button states: disabled when `!form.formState.isValid && form.formState.isSubmitted` (not submitted yet: enabled, form handles validation on submit attempt) OR `form.formState.isSubmitting` (spinner inside button + disabled).

### Edit flow

- Click `Editar` on card → opens sheet with pre-filled values → same submit flow, uses `useUpdateWishlist`.

### Pause/Resume flow

- Click `Pause` / `Play` icon → immediate optimistic toggle → `useUpdateWishlist` with `{status: "paused" | "active"}` → toast.
- Paused cards render with `opacity-70` and dashed border (preserved from Phase 5).
- Paused cards are sorted to the bottom of the grid.

### Delete flow

- Click `Trash2` icon → `AlertDialog` opens with destructive confirmation copy.
- Confirm → `useDeleteWishlist(id)` → soft delete (status="archived" in DB, filtered out of hook response) → toast.
- Cancel → AlertDialog closes, no-op.
- **Important:** replace the Phase 5 native `confirm()` call with `AlertDialog`. Native browser confirm is out of contract.

### Preview pane

- Lives inside the sheet (not outside). Position: below all form fields, above the footer, sticky behavior **not** required.
- Debounced 400ms from last form change.
- Shows skeleton while debouncing (`Skeleton` shadcn primitive, 2 lines).
- Count is bold, uses `text-[#4C46DC]` for visual tie-in to primary action — this is the ONE exception in body copy where accent is used on text (prominence is the whole point).
- Example listings (3 cards) render as compressed `Card` primitives: photo (square aspect, rounded-md), title, price, km, ano, UF. No interactive elements (not links, no CTAs).
- If `useListingsSnapshot()` returns `[]`, preview count is `0` and copy falls back to the zero-match string.

### Onboarding wizard integration

- Onboarding page at `/app/onboarding` (exists from Phase 6). Phase 7 adds a **step 3** to the existing 2-step wizard: "Primeira wishlist".
- Reuses `WishlistFormSheet` fields **inline** (not inside a sheet — rendered directly on the onboarding page, full-width card with generous padding). Hero Fraunces h1 above it.
- On save → marks `users.onboarding_complete=true` (already wired by Phase 6 step 2 on generic save; Phase 7 extends the same handler to include wishlist creation as a single transaction).
- If user skips (button `Pular e fazer depois` — secondary, slate-900 text, no accent), `onboarding_complete` still flips to true; user lands on `/app` with empty state.

### Mobile responsiveness

- Module header: subtitle wraps to new line under h1 on mobile; CTA button stacks below header.
- Grid: `grid-cols-1` (mobile) → `md:grid-cols-2` → `xl:grid-cols-3`.
- Sheet becomes full-screen `dialog` (see above).
- LocalidadePicker already responsive (internal `grid-cols-1 md:grid-cols-[120px_1fr]`).
- Preview pane: same layout on mobile, example cards become full-width (stack vertically).
- Chip groups wrap naturally (`flex flex-wrap gap-2`).
- Onboarding wizard: same layout as desktop but reduced hero size (`text-3xl md:text-5xl` → hero; body unchanged).

### Keyboard & a11y

- All form fields have `<Label htmlFor={id}>`.
- ChoiceChip has `aria-pressed` on selected state.
- AlertDialog: focus trap, Esc cancels, Enter confirms (confirm button auto-focused? NO — destructive dialogs should NOT auto-focus confirm. Focus Cancel).
- LocalidadePicker already wired for keyboard (arrow keys inside Command, Enter selects).
- Sheet/Dialog: Esc closes, backdrop click closes, focus traps inside, focus returns to trigger on close.
- Preview pane is `aria-live="polite"` so screen readers hear count changes.
