<objective>
D-07 from 09-CONTEXT.md: PF-only is a hard rule of the matching engine, not a flag. Today the engine has `MatchingOptions.enforcePfOnly` (default true) and the wishlist preview pane (`WishlistPreviewPane.tsx:67`) passes `false` because the mocks predate the rule. The mocks already carry `seller_type: "PF"` on every entry (verified `src/lib/mock-data/preview-listings.ts`), so the flag is now load-bearing for nothing — drop it.

Purpose: single source of truth for "PJ never produces an opportunity." Eliminates the foot-gun where a future caller could accidentally re-enable PJ matching.
Output: simplified engine signature, tests aligned with the new contract.
</objective>
